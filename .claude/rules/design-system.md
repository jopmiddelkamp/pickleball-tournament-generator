# The design system

Material 3's architecture, the app's own brand. `lib/theme.ts` holds every value and emits it as a CSS custom property; `app/globals.css` is written entirely in those properties; `/design` renders a specimen of all of them. `docs/DESIGN-SYSTEM.md` has the full tables and the reasoning.

Three tiers, and a component only ever touches the middle one:

- **`palette`** — raw tones, keyed by HSL lightness. Court, ball, paper, ink, plus the categorical and feedback colours. Never referenced from CSS.
- **Roles** — `--color-*`, `--text-*`, `--radius-*`, `--space-*`, `--elevation-*`, `--brand-*`, `--z-*`. What a value is *for*.
- **Component tokens** — declared on the component that owns them and derived from a role: `--court-line`, `--court-line-soft`, `--court-ring` on `.court`; `--gender-base`, `--gender-ring` on `.gender`; `--chip-glyph` on `.chip`.

## Working in globals.css

No raw colour, type size, shadow, duration or stacking number belongs in the stylesheet. If a value is missing, the role is missing — add it to `theme.ts`. Layout dimensions (paddings, widths, grid tracks) stay as literals; they are not tokens and pretending otherwise would invent a ramp nobody uses.

Typography is applied as five properties, always all five:

```css
font-family:    var(--text-body-sm-font);
font-size:      var(--text-body-sm-size);
font-weight:    var(--text-body-sm-weight);
line-height:    var(--text-body-sm-line);
letter-spacing: var(--text-body-sm-tracking);
```

The `font` shorthand is shorter and wrong: it resets `font-variant-numeric`, which would silently break every column of figures the first time a declaration moved. When a role is only ever numeric, follow it with `font-variant-numeric: tabular-nums`.

Roles that grow on a wide screen (`display-md`, `display-sm`) override only `font-size` with `--text-<role>-size-wide` inside the 720px query. `720px` and `1080px` are literals there because media queries cannot read custom properties; `layout.wide` and `layout.wider` in `theme.ts` are the source.

## Working in components

Reach for an existing class before adding markup-level styling. `.row--split`, `.row--baseline`, `.label--inline`, `.screen__section`, `.plain-list`, `.tabular` and `.visually-hidden` exist because the same inline styles kept reappearing.

A `style` attribute is acceptable for a genuinely one-off position — a margin on one element on one screen — and its value should still be a `--space-*` token. Anything that describes what a thing *is* rather than where it sits belongs in a class.

## Adding a token

Add it to the right structure in `theme.ts`; `cssVariables` is generated by walking them, so emission follows automatically. This matters more than it sounds: `--white` was once used eleven times in the stylesheet and never listed in the hand-written emission map, so cards, inputs and panels rendered transparent and the gender chips lost their white letters. Undefined custom properties are legal CSS and nothing complains.

`test/theme.test.ts` checks both directions — every property read is emitted, every property emitted is read. A new token with no consumer fails the suite, which is the intended pressure: do not define a role speculatively.

Prefer an existing role. Add one when the new use would change independently of the old — the same test `coding-rules.md` applies to domain logic. Two roles sharing a value is normal and correct (`on-primary` and `surface` are both paper 95); it means a dark scheme can move one without the other.

## Judgment worth keeping

- Levels never get a colour, a tier badge or a position on a scale anywhere a player can see. SPEC-1 §5.
- `--color-focus` and `--color-men` share a value, not a meaning. Do not collapse them.
- `--color-warning` is 3.5:1 — a rule or an icon, never text.
- Print is its own scheme on purpose. Do not "fix" it to match the brand.
- The court card carries the net down the middle and the sideline ring, and nothing else. Sidelines inside the halves were tried and removed: at card size extra strokes box in the names instead of reading as a court.
- The same-gender note is a ruled footnote, not a badge. Ball yellow on a court card means one thing — the player being swapped — and SPEC-1 §5 keeps the night screen free of anything that singles a player out. It is pinned to the bottom of its half so a note on one team never drops the other team's names out of line.
- The gender chip's modifiers set only `--gender-base`; its highlight, shadow and ring are derived. A new category is one line, and tweaking the look is done once on `.gender`.
- Selection is always `--color-primary`, in every choice control. If a new one reaches for a different green, that is the bug.

## Dark theme

The roles are structured for it and the scheme does not exist yet. Adding one is a `darkScheme` in `theme.ts` with the same keys, emitted under `:root[data-theme="dark"]` and `prefers-color-scheme`. If any component CSS needs to change to make it work, a raw value slipped through the role layer — fix that instead.
